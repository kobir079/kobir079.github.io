01

Introduction to OOP

Object Oriented Programming (OOP) is a way of structuring code around objects — self-contained units that bundle data (fields) and behavior (methods) together. Instead of writing a program as a long sequence of steps that operate on loose data (the procedural style), OOP models a program as a set of interacting objects, each responsible for its own state and its own logic.

Every mainstream OOP language, including Java, is built around four core ideas, often called the four pillars: encapsulation, inheritance, polymorphism, and abstraction. This course dedicates a module to each one before moving into interfaces, design principles, and design patterns.

  • Procedural style: functions operate on data passed around between them.
  • Object oriented style: data and the functions that operate on it live together inside an object.

Java example

A tiny first look at an object Car.java
public class Car {
    // fields (state)
    private String model;
    private int speed;

    // constructor
    public Car(String model) {
        this.model = model;
        this.speed = 0;
    }

    // method (behavior)
    public void accelerate(int amount) {
        speed += amount;
        System.out.println(model + " is now going " + speed + " km/h");
    }

    public static void main(String[] args) {
        Car myCar = new Car("Corolla");
        myCar.accelerate(20);
        myCar.accelerate(15);
    }
}
02

Classes & Objects

A class is a blueprint — it declares what fields and methods every object built from it will have. An object is a concrete instance of that blueprint, created with the new keyword, living in memory with its own copy of the instance fields.

The constructor is a special method, matching the class name, that runs automatically when an object is created — it's the natural place to set up initial state. The keyword this refers to the current object, and is most often used to disambiguate a field from a constructor parameter with the same name.

Java example

Class, constructor, and object creation Student.java
public class Student {
    private String name;
    private int roll;

    public Student(String name, int roll) {
        this.name = name;   // this.name = field, name = parameter
        this.roll = roll;
    }

    public void introduce() {
        System.out.println("Hi, I'm " + name + ", roll no. " + roll);
    }

    public static void main(String[] args) {
        Student s1 = new Student("Kobir", 79);
        Student s2 = new Student("Alam", 12);
        s1.introduce();
        s2.introduce();
    }
}
03

Encapsulation

Encapsulation means hiding an object's internal state and only exposing it through a controlled interface — typically public methods. Fields are marked private so outside code cannot set them directly to invalid values; instead, getters and setters mediate access, and setters can validate before accepting a change.

This matters because it protects an object's invariants. A BankAccount should never be able to hold a negative balance just because some other class assigned to it directly — encapsulation makes that impossible by construction.

Java example

Private fields guarded by validating methods BankAccount.java
public class BankAccount {
    private double balance;

    public BankAccount(double openingBalance) {
        this.balance = openingBalance;
    }

    public double getBalance() {
        return balance;
    }

    public void deposit(double amount) {
        if (amount <= 0) throw new IllegalArgumentException("Deposit must be positive");
        balance += amount;
    }

    public void withdraw(double amount) {
        if (amount > balance) throw new IllegalStateException("Insufficient funds");
        balance -= amount;
    }

    public static void main(String[] args) {
        BankAccount acc = new BankAccount(1000);
        acc.deposit(500);
        acc.withdraw(200);
        System.out.println("Balance: " + acc.getBalance()); // 1300.0
    }
}
04

Inheritance

Inheritance lets one class (the subclass) reuse and extend the fields and methods of another (the superclass), using extends. It models an IS-A relationship — a Dog IS-A Animal. The subclass automatically gets everything non-private from the parent, and can add new members or override existing ones.

The keyword super is used inside a subclass to call the parent's constructor or an overridden parent method explicitly.

Java example

A subclass extending a shared parent Animal.java
public class Animal {
    protected String name;

    public Animal(String name) {
        this.name = name;
    }

    public void eat() {
        System.out.println(name + " is eating");
    }

    public void makeSound() {
        System.out.println(name + " makes a generic sound");
    }
}

class Dog extends Animal {
    public Dog(String name) {
        super(name); // calls Animal's constructor
    }

    @Override
    public void makeSound() {
        System.out.println(name + " barks: Woof!");
    }

    public static void main(String[] args) {
        Dog d = new Dog("Tommy");
        d.eat();        // inherited from Animal
        d.makeSound();  // overridden in Dog
    }
}
05

Polymorphism

Polymorphism means "many forms" — the same method call behaves differently depending on the actual object involved. Java has two kinds:

  • Compile-time (overloading): multiple methods share a name but differ in parameters; the compiler picks the right one.
  • Runtime (overriding): a subclass redefines a parent method; the version that actually runs is decided by the object's real type, not its declared type — this is called dynamic dispatch.

Java example

Runtime polymorphism across a shape hierarchy Shape.java
abstract class Shape {
    public abstract double area();
}

class Circle extends Shape {
    private double radius;
    public Circle(double radius) { this.radius = radius; }
    public double area() { return Math.PI * radius * radius; }
}

class Rectangle extends Shape {
    private double w, h;
    public Rectangle(double w, double h) { this.w = w; this.h = h; }
    public double area() { return w * h; }
}

public class ShapeDemo {
    public static void main(String[] args) {
        Shape[] shapes = { new Circle(3), new Rectangle(4, 5) };
        for (Shape s : shapes) {
            // the correct area() runs based on the OBJECT's real type
            System.out.println(s.getClass().getSimpleName() + " area: " + s.area());
        }
    }
}
06

Abstraction

Abstraction means exposing only what a caller needs to know, and hiding how it's actually done. In Java this is expressed with abstract classes (which can mix concrete and abstract methods) and interfaces (pure contracts). An abstract method has no body — subclasses are forced to provide one.

The payoff: calling code depends on a stable contract, not on the details of how each implementation works internally — so implementations can change freely.

Java example

Abstracting "how to pay" behind one contract Payment.java
abstract class Payment {
    public abstract void process(double amount);

    public void receipt(double amount) {
        System.out.println("Receipt for $" + amount);
    }
}

class CreditCardPayment extends Payment {
    public void process(double amount) {
        System.out.println("Charging $" + amount + " to credit card");
    }
}

class PaypalPayment extends Payment {
    public void process(double amount) {
        System.out.println("Sending $" + amount + " via PayPal");
    }
}

public class CheckoutDemo {
    public static void main(String[] args) {
        Payment payment = new PaypalPayment(); // could be swapped freely
        payment.process(49.99);
        payment.receipt(49.99);
    }
}
07

Interfaces

An interface declares method signatures with no implementation (plus optional default methods since Java 8) and no state of its own. A class implements an interface with implements, promising to fill in every abstract method. Unlike class inheritance, a single class can implement multiple interfaces — this is how Java gets the benefits of multiple inheritance of type without the "diamond problem" of multiple inheritance of state.

Java example

One class, two independent behavior contracts Duck.java
interface Flyable {
    void fly();
}

interface Swimmable {
    void swim();
}

class Duck implements Flyable, Swimmable {
    public void fly() {
        System.out.println("The duck flies low over the pond");
    }
    public void swim() {
        System.out.println("The duck paddles across the pond");
    }

    public static void main(String[] args) {
        Duck d = new Duck();
        d.fly();
        d.swim();
    }
}
08

Access Modifiers & Packages

Java controls visibility with four access levels: private (class only), default / package-private (same package), protected (same package, plus subclasses elsewhere), and public (everywhere). Choosing the narrowest level that still works is a direct extension of encapsulation — it limits how much of a class's internals the rest of the codebase can depend on.

Packages group related classes under a namespace (e.g. com.kobir079.banking), which avoids name clashes and lets package-private members act as an "internal API" visible only within that package.

Java example

Access levels side by side Visibility.java
package com.kobir079.banking;

public class Visibility {
    private int secret = 1;        // only inside this class
    int packageVisible = 2;        // only inside com.kobir079.banking
    protected int forSubclasses = 3; // package + subclasses elsewhere
    public int forEveryone = 4;    // accessible from any package
}
09

SOLID Principles

SOLID is a set of five design guidelines that keep object-oriented code flexible and easy to change as requirements grow.

  • S — Single Responsibility: a class should have one reason to change.
  • O — Open/Closed: open for extension, closed for modification — add behavior via new code, not by editing existing working code.
  • L — Liskov Substitution: a subclass should be usable anywhere its parent type is expected, without breaking correctness.
  • I — Interface Segregation: prefer several small, focused interfaces over one large one that forces classes to implement methods they don't need.
  • D — Dependency Inversion: depend on abstractions (interfaces), not on concrete implementations.

Java example

Dependency Inversion in practice NotificationService.java
interface MessageSender {
    void send(String message);
}

class EmailSender implements MessageSender {
    public void send(String message) { System.out.println("Email: " + message); }
}

class SmsSender implements MessageSender {
    public void send(String message) { System.out.println("SMS: " + message); }
}

// depends on the ABSTRACTION, not a specific sender
class NotificationService {
    private final MessageSender sender;

    public NotificationService(MessageSender sender) {
        this.sender = sender;
    }

    public void notifyUser(String message) {
        sender.send(message);
    }
}

public class SolidDemo {
    public static void main(String[] args) {
        NotificationService service = new NotificationService(new EmailSender());
        service.notifyUser("Your order has shipped");
    }
}

Intro to Design Patterns

Design patterns are reusable, named solutions to problems that come up repeatedly in object-oriented design. They aren't finished code to copy-paste — they're a shared vocabulary for a proven structure. This module introduces three common ones.

Singleton — exactly one instance

Only one configuration object should ever exist AppConfig.java
class AppConfig {
    private static AppConfig instance;
    private AppConfig() {} // private constructor blocks outside "new"

    public static AppConfig getInstance() {
        if (instance == null) {
            instance = new AppConfig();
        }
        return instance;
    }
}

Factory — delegate object creation

Callers ask for a shape by name, not by class ShapeFactory.java
class ShapeFactory {
    public static Shape create(String type) {
        switch (type) {
            case "circle": return new Circle(1);
            case "rectangle": return new Rectangle(2, 3);
            default: throw new IllegalArgumentException("Unknown shape: " + type);
        }
    }
}

Observer — notify many listeners of one change

Subscribers react automatically when state changes PriceWatcher.java
import java.util.ArrayList;
import java.util.List;

interface PriceListener {
    void onPriceChanged(double newPrice);
}

class Stock {
    private double price;
    private List<PriceListener> listeners = new ArrayList<>();

    public void addListener(PriceListener l) { listeners.add(l); }

    public void setPrice(double price) {
        this.price = price;
        for (PriceListener l : listeners) l.onPriceChanged(price);
    }
}

public class ObserverDemo {
    public static void main(String[] args) {
        Stock stock = new Stock();
        stock.addListener(p -> System.out.println("Trader A sees price: " + p));
        stock.addListener(p -> System.out.println("Trader B sees price: " + p));
        stock.setPrice(101.5);
    }
}
